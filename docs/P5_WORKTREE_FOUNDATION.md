## Implemented contracts

V17 adds hashed credential generations, durable rotation intents/audit, an explicitly opened enrollment window, and retention policy metadata. The agent generates its own random bootstrap identity and sends only its hash; no runtime secret is returned by HTTP. An interrupted bootstrap retains a current-user DPAPI candidate. Rotation writes `identity-next.dpapi` atomically before committing the hash, acknowledges with the new key, then atomically replaces the current identity. A lost commit response is recovered by trying the persisted candidate first. Stale credentials and sessions are fenced; emergency revoke closes the session and requests cancellation of active work. Enrollment requires both the environment enrollment secret and a bounded operator-opened window. Existing DPAPI identities remain valid at generation 1; older name-only enrollment clients must upgrade.

Operator routes are `/api/v2/agent-credentials` (sanitized inventory), `/{id}/rotate`, `/{id}/revoke`, `/enrollment`, and PUT `/retention`. Runtime credentials can only use their separately authenticated `/api/v2/agent-runtime/credentials/*` routes. PostgreSQL stores hashes and lifecycle metadata, never plaintext runtime tokens. No Codex/Gemini auth profile or cache is read or copied.

Retention defaults are logs 7 days, temporary worktrees 7 days and artifact metadata 90 days, with referenced evidence preservation mandatory. Configuration is durable and bounded. **No automatic retention/deletion sweep is implemented**: metadata remains retained and removal is an explicit, proven-safe worktree operation. This avoids deleting immutable publication/handoff evidence.

V18 adds repository registry, provider capability metadata, validated task contracts, workspace ownership/checkpoints/events and admission reservations. Operator routes under `/api/v2/coding` expose inventory, repository registration/enabled state, workspace prepare/operations, budget policies and admission checks. The runtime only receives repositories assigned to its identity and reports verified refs, public CLI capability and fenced checkpoints. Registry path, origin, branch policy and owner configuration are immutable; enabled state can be changed explicitly.

The backend checks canonical existing primary repositories and credential-free HTTPS origin metadata. The Windows agent independently requires the repository below an explicit `CREATORFLOW_REPOSITORY_ROOTS` parent allowlist, rejects reparse/symlink traversal and non-primary repositories, verifies current-user Git ownership, exact origin and approved ref/commit. Registration does not clone or contact the metadata origin. A registered path does not itself grant access on the agent.

Workspace paths and `creatorflow/<UUID>` branches are generated by the backend under agent storage. No task accepts a repository/executable path or Git command. Fixed argv operations inspect Git state, allocate an exact-commit worktree, and perform non-force clean removal. Hooks, fsmonitor, submodule recursion, external credentials/protocols, global/system configuration and attributes are disabled; local include/filter/worktree configuration and tracked symlink/submodule entries are rejected. Git's own ownership checks remain enabled. See official [worktree semantics](https://git-scm.com/docs/git-worktree) and [configuration controls](https://git-scm.com/docs/git-config).

An agent root lock, per-workspace OS writer lock, database agent/task session/attempt/lease fencing and durable local creation journal protect ownership. Checkpoints are committed before task success. Reuse requires matching repository/configuration/base/branch/agent/allocation identity and checkpoint evidence. Dirty, ignored, missing or mismatched evidence is retained for reconciliation. Lease expiry never blindly retries an allocation or deletes it. Cleanup requires a reconciled READY checkpoint, no dirty/ignored files, the exclusive writer lock and matching Git administrative ownership; no force removal or branch deletion. An interrupted cleanup can only be reconciled when both journal and actual Git inventory prove removal. Windows Job Objects bound process trees, output, timeout and cancellation.

Strict bounded contracts carry repository, exact base, roles, scope/files/prohibited paths, objective, timeout/attempts, provider/budget references and checkpoints. Only WORKTREE_PREPARE, WORKTREE_INSPECT, WORKTREE_CLEANUP and CODING_PREFLIGHT are accepted. CODEX_EXECUTE/GEMINI_EXECUTE return NOT_ENABLED; existing fixture/DAG creation routes cannot enqueue these new kinds. Scope metadata is foundation for P5-02 and does not authorize a coding executor.

Admission requires enabled operator policy, an online non-revoked agent, recent installed capability and same-agent fresh Codex App Server snapshots. Exhaustion produces WAIT_FOR_RESET; missing, stale or incomplete windows require an operator; Gemini quota remains PROVIDER_UNSUPPORTED. Both available quota windows must support readiness; no percentage is invented. Git/FFmpeg/probe/worktree preparation bypass AI quota. Per-agent transactional reservations prevent concurrent policy over-allocation. Budgets are **planned wall-clock seconds**, not token usage, currency or a provider guarantee. Reservations expire after 60 seconds. Replaying an admission ID returns the historical decision, never an execution ticket; P5-02 must revalidate immediately before execution. All responses retain `executionEnabled=false`.
