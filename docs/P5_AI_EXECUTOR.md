Scope/objective data never becomes executable arguments; objective goes to stdin. Version support is deliberately pinned to 0.162.1 until another version is independently verified. Generated schema alone is not execution acceptance.

## Backend lifecycle and authority

V19 adds `coding_executions`, exact expiring `coding_execution_authorizations`, current-session capability evidence and sanitized event history. Execution contract JSON is immutable at the database layer. It binds task/workspace/repository/base commit, clean foundation checkpoint, repository configuration hash, exact files, Codex provider, objective, one attempt, bounded duration, exact budget policy ID **and policy fingerprint**. Repository paths, executable paths, shell commands, model flags, arbitrary tools and Gemini execution are not accepted by the schema.

The feature switch `creatorflow.codex-execution-enabled` / `CREATORFLOW_CODEX_EXECUTION_ENABLED` defaults **false** and remains false during acceptance. Enabling it never supplies task authorization, sandbox evidence or quota. Operator authorization uses the existing authenticated local operator identity, an exact contract hash, explicit AUTHORIZE_CODEX confirmation and 2-15 minute expiry. Runtime credentials cannot call operator APIs, and operator bearer tokens cannot impersonate an agent-runtime identity. Rotation/revocation generation, expiry/revocation, workspace checkpoint/configuration changes and budget policy changes fence authority. Historical admission READY is not reused.

Operator API:

- GET/POST `/api/v2/coding/executions` inventory or strict draft creation.
- POST `/api/v2/coding/executions/{id}/authorize` exact contract confirmation.
- POST `/api/v2/coding/executions/{id}/cancel` durable cancellation/revocation.

Authenticated agent API under `/api/v2/agent-runtime/coding/executions`: capability, claim, `{id}/begin`, `{id}/renew`, `{id}/result`. Claim checks fresh capability/session/credential, exact authorization and current same-agent Codex quota/budget using existing admission. Begin checks them again after local workspace/sandbox preflight, immediately before the CLI invocation. It is single-use: a lost begin response requires reconciliation, never an automatic rerun. Quota checks use the latest fresh PostgreSQL snapshots from the existing read-only collector; no inference is used to measure quota. They are not a provider guarantee.

Execution claims and existing AgentQueue claims serialize on the same agent row; both check active ownership. An authorized execution blocks competing foundation operations on its workspace. There is no new DAG, generic shell executor or dependency scheduler. New records supply an explicit execution/approval lifecycle beside existing fixture tasks and share identity, repository/worktree, budget and usage services.

States: DRAFT -> AUTHORIZED -> CLAIMED -> RUNNING -> REVIEW_REQUIRED, with BLOCKED/CANCEL_REQUESTED/CANCELLED/FAILED/NEEDS_RECONCILIATION branches. Claim leases are 12 seconds; runtime renews during inspection/probe/CLI execution. Cancellation kills the owned process tree; deadline/lease/session loss prevents unfenced success. Expiry/restart cannot requeue a started attempt; uncertain or dirty worktrees require reconciliation. READY is never assigned to a dirty result. REVIEW_REQUIRED has no automatic push, commit, merge, deploy, publication or review/PR pipeline.

## Agent and evidence

The existing current-user DPAPI enrollment/session/rotation, worktree manager and Windows Job Object are reused. A fresh identity was enrolled for this cycle; the old revoked P5-01 identity and orphan were untouched. Native Codex is resolved from the fixed official installation layout, never from task input. Child environments strip CreatorFlow/database/provider credential variables; Codex retains its normal provider-owned authentication resolution internally. No authentication profile/cache was copied or opened by CreatorFlow.

Only existing UTF-8 text files of bounded size are supported in this first adapter. Scopes are exact relative filenames, with no globs/traversal/hidden credential paths, executable scripts, package manifests or instruction files. Before execution, the agent verifies repository root/origin/configuration, actual common Git directory, generated branch, exact base, clean state, checkpoint journal, single writer, non-reparse paths and single-link regular files. It persists START_INTENT before the single-use begin. A restart seeing that journal refuses to invoke the adapter or overwrite retained dirty bytes.

The proposed native command uses an explicit MXC deny-root/minimal/exact-file permission profile with network disabled, no shell tools/unified exec, hooks, apps, plugins, web search or user configuration/rules. Project/ancestor Codex configuration and unverified machine integration configuration are rejected. The native adapter is present but this command has not been exercised with inference, so its end-to-end behavior is **not TESTED**. Unexpected shell/MCP execution events cannot be accepted as a successful result. Configuration/OS enforcement must be proven before live use; post-run checks alone are not a sandbox.

After adapter completion, fixed Git inspection collects diff/changed files and checks scope, file type, clean base identity and sensitive evidence. Secret-bearing or invalid evidence is withheld, retaining local bytes for reconciliation. PostgreSQL stores bounded diff, diff SHA-256, changed files, checkpoint ID, evidence hash, fenced session/attempt and sanitized error/events. No raw CLI event stream, command output, provider response, prompt transcript or authentication data is persisted. Error paths save metadata hashes and retain work rather than silently undo it.
